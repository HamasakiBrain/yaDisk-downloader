# Yandex Disk Downloader

Расширение Chrome Manifest V3 для скачивания файлов Яндекс Диска одним ZIP. Для публичных ссылок (`/d/...`) обходятся все вложенные папки, структура сохраняется в архиве. В личном Диске (`/client/...`) берутся только файлы текущего раздела. Русский popup показывает количество, известный размер, прогресс, отмену и отчет об ошибках. Закрытие popup не останавливает операцию.

## Установка

1. Откройте [Releases](https://github.com/HamasakiBrain/yaDisk-downloader/releases/latest) и скачайте `yandex-disk-downloader-*.zip`.
2. Распакуйте архив в постоянную папку, например `Документы\yandex-disk-downloader`. Chrome не устанавливает ZIP напрямую. Папку после установки нельзя перемещать или удалять.
3. Откройте `chrome://extensions/` и включите **Режим разработчика** (переключатель справа вверху).
4. Нажмите **Загрузить распакованное расширение** и выберите распакованную папку с `manifest.json`.
5. Закрепите значок расширения на панели (иконка пазла → булавка).

Chrome 120 или новее.

**Обновление:** скачайте новый архив из Releases, распакуйте поверх старой папки, на `chrome://extensions/` нажмите ↻ у расширения и обновите вкладку Диска.

## Использование

1. Откройте папку на `disk.yandex.ru` / `disk.yandex.com` — свою (войдите обычным способом) или публичную ссылку `https://disk.yandex.ru/d/...`.
2. Нажмите значок расширения. Список файлов соберётся автоматически, будут показаны количество и общий размер.
3. Нажмите **Скачать всё архивом**. Для публичных ссылок в архив попадают все вложенные папки с сохранением структуры; в личном Диске — файлы текущего раздела.
4. Окно расширения можно закрыть — скачивание продолжится. Не закрывайте и не переключайте вкладку Диска на другой раздел до завершения.
5. Готовый ZIP появится в загрузках Chrome; кнопка **Показать ZIP** открывает его расположение. Если отдельные файлы не скачались, их список с причинами будет показан в окне.

Расширение не является продуктом Яндекса и не связано с компанией Яндекс.

## Как работает

Content script собирает стабильные DOM-идентификаторы, имена и доступные размеры во всем текущем списке, включая виртуализованные строки. Прокрутка возвращается на исходное место. Папки распознаются отдельно; неизвестный тип, отсутствие идентификатора или незавершенная загрузка приводят к ошибке, а не к скачиванию заведомо неполного списка.

Для нескольких файлов с различными именами расширение очищает прежнее выделение, выбирает только найденные файлы и вторым проходом проверяет выделение. Затем нажимает штатную кнопку «Скачать». Яндекс формирует архив, Chrome скачивает его с именем `yandex_disk_download_YYYY-MM-DD.zip`. На этом пути упаковку выполняет Яндекс; данные не пересылаются дополнительным сервисам. Это приоритетный механизм из задания, описанный в [справке Яндекса](https://yandex.ru/support/yandex-360/customers/disk/web/ru/actions-files/download.html?lang=ru).

Для одного файла и совпадающих имен используется локальная упаковка zip.js. Каждый файл выбирается через интерфейс; берется доступная ссылка скачивания или кратковременно запускается штатная загрузка файла. Связанная загрузка отменяется, а полученная временная ссылка читается в скрытом документе расширения. Файлы последовательно сохраняются в OPFS и добавляются в ZIP без изменения байтов. В памяти не хранится весь архив. ZIP использует метод STORE без сжатия, поддерживает Unicode и ZIP64. Совпадающие имена получают суффиксы ` (2)`, ` (3)` перед расширением. Разделители пути и управляющие символы в имени заменяются на `_`, чтобы запись не выходила из корня ZIP.

Загрузка сопоставляется только при совпадении адреса источника, времени запуска и ожидаемого имени (либо ZIP для штатного режима). Chrome не предоставляет идентификатор исходной вкладки в Downloads API. Поэтому **не запускайте одновременно другие загрузки из того же раздела Диска**. Если браузер скрывает referrer, надежно связать загрузку невозможно: расширение не вмешивается в нее и сообщает об ошибке ожидания. Файл при этом может оказаться в обычных загрузках Chrome.

Проценты штатного режима относятся к передаче ZIP; во время серверной подготовки процент неизвестен. Количество файлов в этом режиме — число выбранных файлов, после сохранения — ожидаемое число в архиве; содержимое серверного ZIP отдельно не перечитывается. Локальный режим показывает число добавленных файлов и ошибки по каждому имени. Сбой одного HTTP-запроса не мешает остальным файлам. Ошибка записи ZIP или нехватка места останавливает операцию. Успех отображается только после состояния `complete` в Chrome Downloads API, частичный результат явно отмечается.

## Ограничения

- DOM-интерфейс Яндекса не является стабильным API. Изменения классов, атрибутов, элементов выделения или скрытое выделение в нестандартных разделах могут потребовать обновления `content.js`. Поддерживаются распознаваемые списки и плитки; универсальная работа со всеми разделами/вариантами интерфейса без проверки на аккаунте не гарантируется.
- Корзина и история изменений не поддерживаются. Недоступные файлы, запрет скачивания, CAPTCHA, лимиты сервиса и истекшая сессия не обходятся. Встроенный серверный архив не позволяет получить пофайловую причину ошибки; расширение показывает ошибку всего сохранения.
- Если штатный архив не запускается, автоматическая повторная загрузка не выполняется: это предотвращает дублирование. Локальный режим доступен для одного файла и совпадающих имен; он тоже требует рабочей кнопки выделения/скачивания или доступной прямой ссылки.
- Нельзя менять раздел, закрывать или перезагружать вкладку во время операции. Отмена останавливает действия расширения и связанную загрузку Chrome; уже начатая серверная подготовка Яндекса может продолжаться. Отмененный незавершенный файл может остаться в истории Chrome.
- Для OPFS требуется свободное место под ZIP и один текущий файл. Квота зависит от браузера и диска. Предельное время одного HTTP-потока — 5 минут, ожидание начала одного файла — 25 секунд, штатного ZIP — 2 минуты, одного прохода списка — 4 минуты. При постоянной или очень медленной подгрузке сбор останавливается. Новые файлы, появившиеся после снимка, не входят в операцию.
- При полном перезапуске браузера операция не возобновляется. На существующей загрузке Chrome это не отражается. Расширение не создает OAuth-токены и не обращается к приватным endpoint Яндекса.

## Разработка и проверки

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd run check
npm.cmd test
npm.cmd run test:browser
```

Сборка копирует локальную библиотеку zip.js и лицензию, генерирует PNG-иконки, готовую папку и ZIP установки. В расширении нет CDN-скриптов, удаленного исполняемого кода или `eval`. Для браузерных тестов используется имеющийся Chromium из кэша Playwright; при другом расположении задайте `CHROMIUM_PATH`.

Автотесты используют локальные контролируемые страницы с разметкой Диска и имитированными HTTP-ответами. Они проверяют алгоритмы и интеграцию расширения с Chrome, но не заменяют проверку реального аккаунта Яндекс Диска. Проверенный объем и непроверенные сценарии записаны в `TESTING.md`.

Исходники: `background.js` — оркестрация и состояние; `content.js` — DOM, прокрутка, выделение; `download-manager.js` — сопоставление загрузок; `offscreen.js` — скрытый исполнитель; `zip-manager.js` — потоковый ZIP; `popup.*` — интерфейс. Подробности обработки данных — в `PRIVACY.md`.
